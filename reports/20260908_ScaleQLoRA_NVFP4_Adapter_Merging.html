1. Scale-QLoRA: Code-Invariant Adapter Merging for Native 4-bit Microscaling LLMs

Scale-QLoRA — 在原生 4-bit 微縮格式（NVFP4 / MXFP4）上，把 LoRA 適配「合併」從一個破壞性操作轉為位元恆等的代碼不變操作

核心思想

將 LoRA adapter 合併回基底模型是標準的部署實踐：它消除了推理期 adapter 的 per-forward 開銷，留下單一可被任何 serving stack 載入的獨立 checkpoint。然而，在原生 4-bit 微縮格式（microscaling）的 checkpoint（如 NVFP4、MXFP4）上，這一步不再「免費」。

問題的根源在於：合併後的權重必須透過量化器（quantizer）重新寫回，而這會重新推導 checkpoint 的離散 E2M1 code plane（約佔 artifact 位元組數的 90%）。這意味著部署 artifact 被耦合到某一個特定的量化慣例（quantization convention），且其生命週期中後續任何觸及 code plane 的操作都可能讓它偏移。

更嚴重的後果：若草率處理，這一步不只是脆弱 —— 它會刪除適配成果，退化幅度高達 39 個百分點（39 pp）。原因在於：當基底已經「在格點上」（on-grid）時，重建的最優解就是基底本身，adapter 帶來的適配訊號會在重新量化過程中被抹平。

Scale-QLoRA 提出了一個截然不同的路徑：只調整原生 per-block scale 欄位，在部署格點上訓練這些 scale，並凍結每一個 E2M1 code。在固定的原生格式、scale grid、block layout 與 code plane 之下，合併就成為一個位元恆等（bit-exact identity）操作，合併後的 artifact 是 code-invariant 的。

關鍵洞見：不要去動那 90% 的 code plane。LoRA 的適配訊號完全可以由 per-block scale 欄位承載 —— 只要 scale 在部署格點上訓練、code 被凍結，合併就是一個零誤差的恆等映射，部署 artifact 的生命週期穩定性由此而來。

方法與演算法

直覺範例 — 兩種修圖師傅：想像一張已經用 4-bit 網點印刷輸出的海報（原生 4-bit microscaling checkpoint）。每個小方塊（block）有一個「墨色濃度旋鈕」（per-block scale），方塊內的網點圖案（E2M1 code）已經固定印好。

傳統合併（naive merge）像是一位師傅把整張海報重新製版：他先算出加了 LoRA 修正後的連續色值，再重新輸出網點 —— 但重新製版會讓原本的網點圖案全部被覆蓋成新的，而且不同印刷廠（量化慣例）印出來的網點還不一樣。最糟的情況下，因為基底本來就是網點的最佳近似，重新製版的結果幾乎等於原圖，LoRA 的修正被抹掉了。

Scale-QLoRA則是另一位師傅：他完全不碰網點圖案，只轉動每個方塊的墨色濃度旋鈕，把旋鈕調到能表現 LoRA 修正的程度。因為網點沒動，合併就是把旋鈕設定寫死 —— 零誤差、可回滾、任何印刷廠都讀得懂。

原生 4-bit 微縮格式結構

要理解 Scale-QLoRA，必須先理解原生 4-bit 微縮格式的資料結構。以 NVFP4 / MXFP4 為代表，這類格式將權重矩陣切分為多個連續的 block（例如每 32 個元素一塊），每個 block 由兩部分組成：

  • E2M1 code plane（碼面）：每個元素以 4-bit E2M1 浮點編碼（1 符號 + 2 指數 + 1 尾數），可表示有限的一組離散值（如 $\{0, \pm0.5, \pm1, \pm1.5, \pm2\}$ 等）。這部分約佔 artifact 位元組數的 90%。
  • Per-block scale（每塊縮放因子）：每個 block 伴隨一個共享的 scale 值（通常以 8-bit 格式儲存，如 E8M0 指數或 E4M3）。權重的真實值為 $W \approx S \cdot C$，其中 $S$ 為 block scale、$C$ 為 code。

這種「粗粒度 code + 細粒度 scale」的設計讓 microscaling 格式能在低位元下保持比傳統 INT4 更好的數值動態範圍，是新一代硬體（NVIDIA Blackwell 等）原生支援的 4-bit 格式。

為何 naive merge 會重新推導 codes 並耦合到量化慣例

標準 LoRA 合併的流程是：$W_{\text{merged}} = W_{\text{base}} + \Delta W = W_{\text{base}} + BA$（$B, A$ 為 LoRA 低秩矩陣）。但在原生 4-bit checkpoint 上，$W_{\text{base}}$ 是以「scale + code」形式儲存的，合併後的連續值 $W_{\text{merged}}$ 必須重新通過量化器寫回成新的 scale + code。這會引發連鎖問題：

  1. Code plane 被重新推導：量化器對 $W_{\text{merged}}$ 重新做 round-to-grid，產生新的 E2M1 codes。這些新 codes 佔 artifact 的 90%，意味著部署 artifact 被實質「重製」。
  2. 耦合到量化慣例：不同的 rounding 規則（nearest、stochastic、甚至不同硬體的實作差異）會產生不同的 codes。部署 artifact 從此被綁定到某一個量化慣例。
  3. 生命週期不穩定：後續任何觸及 code plane 的操作（再量化、格式轉換、跨硬體部署）都可能讓 codes 再次偏移。
  4. 適配被刪除（最嚴重）：因為 $W_{\text{base}}$ 已經是 on-grid 的，對 $W_{\text{merged}}$ 做最近鄰重建時，重建最優解會傾向回到 $W_{\text{base}}$ 的 grids，LoRA 帶來的 $\Delta W$ 適配訊號被抹平 —— 退化達 39 pp。

Scale-QLoRA 的 scale-only 適配

Scale-QLoRA 的核心設計原則：只調 scale，不動 code。具體而言：

  1. 凍結 E2M1 code plane：基底模型的 codes 在整個訓練與合併過程中完全不變。
  2. 在部署格點上訓練 per-block scale：將 LoRA 的適配能力限制在 scale 欄位的調整上。Scale 在原生格點（deployment grid）上訓練，確保訓練時所見即部署時所得。
  3. 固定原生格式、scale grid、block layout：整個流程在單一、固定的原生格式內進行，不做跨格式轉換。

位元恆等的合併恆等式

在上述條件滿足時，合併成為位元恆等操作：

  • Code plane 未變，合併前後的 codes 完全一致（bit-exact）。
  • Scale 欄位已是訓練結果的部署值，合併就是把訓練後的 scale 直接寫入 checkpoint，無需重新量化。
  • 合併後的 artifact 是 code-invariant 的 —— 它與基底共享同一個 code plane。

與 merge-aware QAT-LoRA 的結構性比較

論文將 Scale-QLoRA 與 merge-aware QAT-LoRA 進行比較。兩者在實驗中都是精度無損（accuracy-lossless）的，因此論文不主張兩者之間存在精度排序。它們的差異是結構性的：

維度 Scale-QLoRA Merge-aware QAT-LoRA
適配對象 僅 per-block scale 權重（含 code 與 scale）
Code plane 凍結，合併後 bit-exact 不變 透過量化器重新推導
合併操作 位元恆等（identity） 需重新量化，非恆等
部署 artifact 耦合 不耦合到量化慣例（code-invariant） 耦合到量化慣例
生命週期穩定性 高（code 不動） 低（code 可被後續操作搬動）
訓練期 STE 無需（code 凍結，無 round 端點需直通） 需要（code 經量化器，round 需 STE）
精度 accuracy-lossless accuracy-lossless（與 Scale-QLoRA 無排序）
兩者差異的真正意義在於「生命週期定價」：QAT-LoRA 重新推導 code plane，意味著部署 artifact 的命運被綁在量化器的 rounding 規則上；Scale-QLoRA 保留 code plane，使 artifact 在整個生命週期中對 code-touching 事件免疫。這不是精度之爭，而是工程穩定性之爭。

數學推導

原生 4-bit 微縮格式的反量化

設權重矩陣 $\mathbf{W}$ 被劃分為 $K$ 個 block，第 $k$ 個 block 的元素記為 $\mathbf{w}^{(k)} \in \mathbb{R}^{n_b}$（$n_b$ 為 block size，如 32）。microscaling 格式將每個 block 編碼為一個共享 scale $s^{(k)}$ 與一組 4-bit E2M1 codes $\mathbf{c}^{(k)}$：

$$ \hat{\mathbf{w}}^{(k)} = s^{(k)} \cdot \mathbf{c}^{(k)}, \quad \mathbf{c}^{(k)} \in \mathcal{G}_{\text{E2M1}}^{n_b} $$

其中 $\mathcal{G}_{\text{E2M1}}$ 為 E2M1 浮點格點（4-bit，含符號、2 指數、1 尾數位元），是一個有限的離散值集合。整個權重的近似為：

$$ \mathbf{W} \approx \mathbf{S} \odot \mathbf{C}, \quad \mathbf{S} = [s^{(1)}, \dots, s^{(K)}], \quad \mathbf{C} = [\mathbf{c}^{(1)}, \dots, \mathbf{c}^{(K)}] $$

其中 $\mathbf{S}$ 為 per-block scale 欄位，$\mathbf{C}$ 為 E2M1 code plane。code plane $\mathbf{C}$ 約佔 artifact 位元組數的 90%。

標準 LoRA 合併與重建最優問題

標準 LoRA 合併後的連續權重為：

$$ \mathbf{W}_{\text{merged}} = \mathbf{W}_{\text{base}} + \Delta \mathbf{W}, \quad \Delta \mathbf{W} = \mathbf{B}\mathbf{A}, \quad \mathbf{B} \in \mathbb{R}^{d \times r}, \mathbf{A} \in \mathbb{R}^{r \times d}, \ r \ll d $$

在原生 4-bit checkpoint 上，$\mathbf{W}_{\text{base}} = \mathbf{S}_{\text{base}} \odot \mathbf{C}_{\text{base}}$ 已是 on-grid。合併後必須重新量化：$\mathbf{W}_{\text{merged}} \to (\mathbf{S}_{\text{new}}, \mathbf{C}_{\text{new}})$。最近鄰重建的目標為：

$$ \mathbf{C}_{\text{new}}^{(k)} = \arg\min_{\mathbf{c} \in \mathcal{G}_{\text{E2M1}}^{n_b}} \left\| \mathbf{w}_{\text{merged}}^{(k)} - s_{\text{new}}^{(k)} \cdot \mathbf{c} \right\|_2^2 $$
退化的數學根源：當 $\mathbf{W}_{\text{base}}$ 已在格點上（on-grid），且 $\Delta \mathbf{W}$ 相對於 block scale 為小量時，重建最優解 $\mathbf{C}_{\text{new}}^*$ 會趨近於 $\mathbf{C}_{\text{base}}$ —— 也就是說，重建最優解就是基底本身，LoRA 的 $\Delta \mathbf{W}$ 被抹平。這正是 naive merge 退化達 39 pp 的原因。

Scale-QLoRA：凍結 codes 使合併成為位元恆等

Scale-QLoRA 將適配限制在 scale 欄位。定義訓練目標為尋找新的 per-block scale $\mathbf{S}_{\text{adapt}}$，同時凍結 $\mathbf{C}_{\text{base}}$：

$$ \mathbf{S}_{\text{adapt}} = \arg\min_{\mathbf{S}} \; \mathcal{L}\!\left( f_{\mathbf{S} \odot \mathbf{C}_{\text{base}}}; \mathcal{D} \right), \quad \text{subject to } \mathbf{C}_{\text{base}} = \text{const} $$

其中 $f$ 為模型前向，$\mathcal{D}$ 為適配任務資料，$\mathcal{L}$ 為任務損失。訓練只在 deployment grid 上調整 $\mathbf{S}$。

合併的位元恆等性

合併後的 artifact 為 $(\mathbf{S}_{\text{adapt}}, \mathbf{C}_{\text{base}})$。由於 code plane 完全未變：

$$ \mathbf{C}_{\text{merged}} = \mathbf{C}_{\text{base}} \quad \text{(bit-exact)}, \quad \mathbf{S}_{\text{merged}} = \mathbf{S}_{\text{adapt}} $$

合併操作 $\mathcal{M}$ 為恆等映射（在 code plane 上）：

$$ \mathcal{M}\!\left( \mathbf{S}_{\text{adapt}}, \mathbf{C}_{\text{base}} \right) = \left( \mathbf{S}_{\text{adapt}}, \mathbf{C}_{\text{base}} \right) \quad \Longrightarrow \quad \mathcal{M}\big|_{\mathbf{C}} = \mathbf{I} $$

即合併在 code plane 上是位元恆等的，合併後 artifact 為 code-invariant。

與 QAT-LoRA 的結構性差異（形式化）

merge-aware QAT-LoRA 在訓練中考慮合併後的重新量化，其 forward 含 fake-quantization 且需 STE：

$$ \hat{\mathbf{W}}_{\text{QAT}} = Q\!\left( \mathbf{W}_{\text{base}} + \mathbf{B}\mathbf{A} \right) = \mathbf{S}_{\text{QAT}} \odot \mathbf{C}_{\text{QAT}}, \quad \mathbf{C}_{\text{QAT}} \neq \mathbf{C}_{\text{base}} $$

其梯度需透過 Straight-Through Estimator 直通 $\text{round}(\cdot)$ 端點：

$$ \frac{\partial \mathbf{C}_{\text{QAT}}}{\partial \mathbf{W}} \approx \frac{\partial\, \text{round}(\mathbf{W})}{\partial \mathbf{W}} \;\stackrel{\text{STE}}{\approx}\; 1 $$

而 Scale-QLoRA 因 $\mathbf{C}_{\text{base}}$ 凍結，訓練過程中完全不需要 STE —— 這也是其在 dense 8B 模型上每步快 3.9x 的數學原因。

精度結果

精度無損：在 4 個模型 × 4 個任務的全面評估中，Scale-QLoRA 與 merge-aware QAT-LoRA都是 accuracy-lossless 的。論文明確聲明不主張兩者之間存在精度排序 —— 它們在精度上是等價的，差異純屬結構性。

生命週期敏感度（核心實驗）

論文將兩者差異定位為「生命週期定價」，並量化了 code-touching 事件對部署 artifact 的影響：

生命週期事件 Scale-QLoRA（code 凍結） QAT-LoRA（code 重推導）
Nearest-rounding 實作差異 不受影響（code 不變） 在量測任務上約 ~1 point 分歧
更極端的規則不匹配 不受影響（code 不變） 權重空間 artifact 可被驅至 ~0%
報告性質 — 作為敏感度上界報告，非部署頻率
敏感度的解讀：論文強調 ~0% 的極端結果是一個敏感度上界（sensitivity bound），而非實際部署中會發生的頻率。它的意義在於揭示：一旦 code plane 被重新推導，部署 artifact 就暴露在 rounding 規則不匹配的風險下，極端情況可完全失效。Scale-QLoRA 透過凍結 code plane，從根本上消除了這類風險。

貢獻與創新

  1. Code-invariant merging（代碼不變合併）：首次提出在原生 4-bit microscaling 格式上，透過凍結 E2M1 code plane、僅調 per-block scale，使 LoRA 合併成為位元恆等操作。這從根本上解決了 naive merge 退化達 39 pp 的問題。
  2. 生命週期穩定性（lifecycle stability）：揭示並量化了 code-touching 事件對部署 artifact 的風險 —— nearest-rounding 分歧約 ~1 point，極端不匹配可至 ~0%。Scale-QLoRA 透過 code-invariance 使 artifact 在整個生命週期中對此類事件免疫。
  3. STE-free 訓練：因 code plane 凍結，訓練中完全移除權重空間的 Straight-Through Estimator，在 dense 8B 模型上實現每步 3.9x 加速。
  4. 精確回滾（exact rollback）：code plane 不變使得回滾操作只需還原 scale 欄位，實現位元精確的回滾能力。
  5. 快速任務切換與 code-plane 去重：多個適配任務共享同一 code plane，scale-only task swap 達 ~125x 加速，並啟用 code-plane deduplication 以節省儲存。
  6. 結構性而非精度的比較視角：明確聲明 Scale-QLoRA 與 merge-aware QAT-LoRA 在精度上等價（無排序），將兩者差異正確定位為生命週期定價問題，為後續 4-bit 部署研究提供了清晰的設計取捨框架。

應用場景

  • 原生 4-bit LLM 的生產部署：在 NVFP4 / MXFP4 硬體上部署 LLM 時，以 Scale-QLoRA 進行任務適配，確保合併後 artifact 穩定、不耦合特定量化慣例。
  • 多任務 serving（multi-task serving）：多個任務的 adapter 共享同一 code plane，僅以 scale 欄位區分，實現 ~125x 的快速任務切換，適合高吞吐多租戶推理服務。
  • 生產環境的回滾與去重：exact rollback 支援安全發布與快速回退；code-plane deduplication 在管理大量適配變體時顯著降低儲存成本。
  • 跨硬體 / 跨量化慣例部署：code-invariant artifact 不受 nearest-rounding 實作差異影響，適合在多種硬體後端、多種 serving stack 間移植。
  • 高效 LoRA 訓練：移除 STE 帶來 3.9x per-step 加速，降低 4-bit 適配訓練的算力門檻，尤其利好 dense 大模型。
  • 量化模型生命週期管理：為需長期維護、多次再量化或格式轉換的 4-bit 模型提供 code-plane 穩定性保障。
未來展望：Scale-QLoRA 確立了「凍結 code、只調 scale」作為 microscaling 格式適配的設計範式。後續可探索：scale 欄位位元配置的最佳化、與其他適配方法（如 prefix tuning、prompt tuning）的結合、在更低位元格式（如 2-bit / 1-bit microscaling）上的推廣、以及 code-plane deduplication 在大規模 adapter 倉儲中的實際壓縮比。
